# JavaScript Coding Rules

この文書は、JavaScript で AI エージェントが実装する際の追加ルールを定義します。  
`common.md` と併用します。

## 1. 基本スタイル

- 既存プロジェクトの ESLint / formatter / package 設定を優先する。
- `var` は使用せず、原則 `const`、再代入が必要な場合だけ `let` を使用する。
- `==` / `!=` ではなく、原則として `===` / `!==` を使用する。
- ES Modules / CommonJS の方式を、既存プロジェクト内で混在させない。
- 暗黙的な型変換に依存した判定を避ける。

## 2. 非同期処理

- Promise ベースのコードでは、原則として `async / await` を優先する。
- Promise を意図せず放置しない。
- 非同期関数の呼び出しでは、`await`, `return`, 明示的な fire-and-forget のいずれかを判断する。
- fire-and-forget では、失敗時の扱いを明確にする。
- callback と Promise を同じ処理系で不用意に混在させない。
- async のループ処理で、逐次実行と並列実行の意図を明確にする。

## 3. エラー処理

- `.catch(() => {})` のようにエラーを握りつぶさない。
- catch したエラーを正常値へ変換する場合、その意味を明確にする。
- 外部 I/O の失敗と、プログラム内部の不整合を区別する。
- エラーオブジェクトの情報を失う再 throw を避ける。
- ユーザー入力・ネットワーク入力など、外部由来データを検証する。

## 4. 状態管理

- モジュール間で可変なグローバル状態を共有しない。
- 状態の所有者を明確にする。
- オブジェクトを共有する場合、どこで変更されるか分からない設計を避ける。
- イベントリスナー、タイマー、購読処理には必要に応じて解除処理を用意する。

## 5. モジュールと責務

- API 通信、ファイル I/O、デバイスアクセス等は service / adapter 等の担当層へ分離する。
- UI、通信、データ変換、ビジネスロジックを 1 ファイルへ混在させない。
- 巨大な util / helper ファイルを作らない。
- 新しい npm package を追加する前に、標準 API または既存依存で実現できないか確認する。

## 6. データ

- オブジェクトの必須項目・任意項目を曖昧にしない。
- 深い optional chaining でデータ不整合を隠さない。
- JSON 等の外部データは、構造が正しいことを前提にしない。
- 数値と数値文字列を混在させない。
- `undefined` と `null` の使い分けは、既存プロジェクトの方針に従う。

## 7. Node.js

Node.js を使用する場合:

- 同期 I/O をサーバーやイベントループ上の通常処理で多用しない。
- process 全体に影響する設定変更を、ライブラリ層で勝手に行わない。
- 環境変数へのアクセスをコード全体へ散在させない。
- stream を扱う場合、error と close / finish の扱いを確認する。

## 8. Browser

ブラウザ環境では:

- DOM 取得失敗の可能性を無視しない。
- イベントリスナーの重複登録に注意する。
- UI 操作とデータ処理を可能な範囲で分離する。
- ユーザー入力を HTML として直接挿入しない。
