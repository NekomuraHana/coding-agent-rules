# Windows Desktop GUI Rules (MFC / C#)

この文書は、主に Visual Studio で開発する Windows デスクトップ GUI アプリケーションを AI エージェントが実装・変更する際の追加ルールを定義します。  
対象には、C++ / MFC、Win32、C# / Windows Forms、WPF、WinUI 等を含みます。

`common.md` および使用言語のルールと併用します。

このルールは言語だけから自動的に適用されることを前提としません。  
MFC や C# の Windows GUI アプリケーションを扱うプロジェクトでは、プロジェクト側の `AGENTS.md` 等から、このファイルを明示的に参照させます。

例:

```text
Windows GUI アプリケーションの実装・変更では、
coding-agent-rules/rules/common.md と
coding-agent-rules/rules/windows-desktop.md を必ず参照すること。
```

## 1. GUI デザインを変更しない

AI エージェントは、明示的な依頼がない限り GUI のデザインに関わる変更を行わない。

対象には、少なくとも次を含む。

- コントロールの追加・削除
- コントロールの位置、サイズ、余白、整列
- ウィンドウやダイアログのサイズ
- 色、フォント、アイコン、画像
- 表示文言やラベル
- レイアウト構造
- タブ順、フォーカス順
- メニュー、ツールバー、ステータスバーの構成
- 表示 / 非表示の条件
- Enabled / Disabled の切り替え条件
- ダイアログ、通知、メッセージ表示方法
- アニメーションや視覚効果

GUI の見た目や操作感を改善することを目的とした自主的な変更も行わない。

既存 GUI に不整合や改善余地が見つかっても、依頼されていない場合は変更せず、必要に応じて報告だけを行う。

## 2. GUI 仕様が曖昧な場合は補完しない

ソフトウェア仕様、Issue、プロンプト等で GUI の振る舞いが明確でない場合、AI エージェントは推測で補完しない。

特に次のような事項が未指定の場合は、必要な指示を仰ぐ。

- 何を表示するか
- いつ表示 / 非表示にするか
- 表示する文字列
- 色や強調方法
- エラーや警告の表示方法
- ボタンや入力欄を有効 / 無効にする条件
- ダイアログを表示するかどうか
- モーダル / モードレスの選択
- フォーカスを移動するかどうか
- 処理中、完了、失敗をどのように見せるか
- 画面遷移やダイアログを閉じるタイミング

既存画面に同一の振る舞いがあり、仕様上もそれへ合わせることが明確な場合は、その既存実装を踏襲してよい。

Windows の一般的な慣習や AI の判断だけを根拠として、プロジェクト固有の GUI 仕様を決めない。

## 3. GUI とバックエンドの責務を分離する

GUI 層には、原則として次の責務だけを持たせる。

- ユーザー操作の受け取り
- 入力値の取得
- バックエンド処理の呼び出し
- バックエンドから得た結果の表示
- GUI の状態管理

業務ロジック、データ変換、通信、ファイル I/O、デバイスアクセス等を、イベントハンドラへ直接実装しない。

既存プロジェクトで Service、Controller、ViewModel、Model 等の責務分離が採用されている場合は、その構造を優先する。

MFC では、`CDialog` / `CDialogEx` / `CView` / `CFrameWnd` 等の GUI クラスへ、GUI と直接関係しない処理を集約しない。

AI エージェントは、GUI 側へ実装する方が簡単という理由だけでバックエンド処理を GUI クラスへ移動しない。

## 4. イベントハンドラを肥大化させない

ボタンクリック、メニュー選択、フォームイベント、MFC のメッセージハンドラ等には、可能な限り次だけを記述する。

1. GUI から必要な入力値を取得する。
2. 必要最小限の入力検証を行う。
3. バックエンドの処理を呼び出す。
4. 結果を GUI に反映する。

長い処理、複雑な条件分岐、通信処理、ファイル処理等をイベントハンドラへ直接追加しない。

## 5. GUI 定義ファイルと自動生成コード

GUI デザイナやフレームワークが管理するファイルは、明示的な GUI 変更依頼がない限り変更しない。

例:

- C++ / MFC の `.rc`, `resource.h` 等のリソース定義
- Windows Forms の `*.Designer.cs`
- Windows Forms / WPF 等の `*.resx`
- WPF / WinUI 等の XAML
- GUI デザイナが生成するコード

自動生成ファイルを手作業で変更する場合は、その方法がプロジェクトで許可されていることを確認する。

既存コントロールへイベント処理を接続するための変更についても、GUI 定義への変更が必要になる場合は影響範囲を確認する。

## 6. MFC 固有のルール

MFC プロジェクトでは、明示的な依頼がない限り次を変更しない。

- ダイアログテンプレート
- コントロール ID
- Menu / String Table / Accelerator 等のリソース
- アイコン、ビットマップ等のリソース
- DDX / DDV の割り当て
- 既存のメッセージマップ構成
- `OnInitDialog()`, `OnOK()`, `OnCancel()` 等の既存 GUI 動作

`BEGIN_MESSAGE_MAP` / `END_MESSAGE_MAP` や `ON_BN_CLICKED` 等へハンドラを追加する場合は、仕様で必要なイベントだけを追加する。

未使用に見えるという理由だけで、既存のメッセージハンドラ、DDX / DDV、コントロール ID、リソースを削除しない。

`resource.h` の ID を整理・採番し直すなど、既存リソース ID に影響する変更を行わない。

Visual Studio のリソースエディタが管理する内容を直接テキスト編集する場合は、プロジェクトの既存運用で許可されていることを確認する。

## 7. UI スレッドをブロックしない

時間のかかる処理を UI スレッド上で実行しない。

対象には、例えば次を含む。

- 通信
- ファイル I/O
- デバイスアクセス
- 長時間の計算
- 待ち時間を伴う処理

非同期処理やワーカースレッドを使用する場合は、既存フレームワークとプロジェクトの方式に従う。

バックグラウンドスレッドから GUI を直接更新せず、MFC のメッセージ通知、Dispatcher、Invoke、SynchronizationContext 等、使用フレームワークに適した方法で UI スレッドへ処理を戻す。

## 8. GUI の既存動作を維持する

バックエンド処理だけを変更する依頼では、原則として既存 GUI の次の動作を維持する。

- 表示内容
- 操作手順
- コントロール状態
- ウィンドウ遷移
- エラー表示
- フォーカス動作
- タイミング

バックエンド変更により GUI 側の変更が避けられない場合は、勝手に変更せず、その必要性と変更候補を報告する。

## 9. エラー処理とユーザー表示を分ける

バックエンドでは、GUI 表示用の文言や色等を直接決定しない。

バックエンドは、GUI が判断できる形で処理結果や失敗理由を返す。

GUI に表示する文言、表示方法、色、ダイアログ種別等が仕様で定義されていない場合は、AI エージェントが独自に決定しない。

## 10. テスト

GUI から分離可能なロジックは、可能な限り GUI を起動せずにテストできる構造とする。

バックエンドの単体テストでは、GUI コントロールや `CWnd` / Window / Form オブジェクトへ直接依存しない。

GUI の見た目や操作確認が必要な項目は、通常の単体テストと区別して扱う。

GUI を実際に確認できない環境では、見た目や操作結果を確認済みとして扱わない。

## 11. AI エージェント向け禁止事項

AI エージェントは、明示的な依頼がない限り次を行わない。

- GUI デザインの変更
- GUI の自主的な改善
- 未指定の色、文言、レイアウト、表示方法の決定
- 未指定の画面遷移やダイアログ動作の決定
- GUI イベントハンドラへの業務ロジックの追加
- バックエンド処理を GUI クラスへ移動すること
- GUI デザイナ生成コードの不用意な直接編集
- MFC リソース ID の整理・変更
- バックエンド変更に便乗した GUI のリファクタリング

GUI に関わる仕様が不足している場合は、実装を推測で進めず、必要な指示を仰ぐ。

## 12. 変更後に報告すること

Windows GUI アプリケーションを変更した場合は、通常の変更報告に加えて次を明記する。

- GUI ファイルを変更したか
- MFC の場合、`.rc` / `resource.h` / メッセージマップ / DDX・DDV を変更したか
- GUI の見た目または操作方法へ影響があるか
- GUI 仕様について未確認事項があるか
- UI スレッド / 非同期処理へ影響があるか
- GUI を実際に起動して確認したか
